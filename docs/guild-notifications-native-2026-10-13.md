# Guild notification cache replacement: named child, not a bare array

The replica now returns `ret_data:{guild_notifications:[]}` for authenticated
`/guild/GetNotifications`. No original notification instances or producer event
policy are reconstructed. Read/delete operations remain refused. No live game,
save, input, APK or DataDump changes occurred.

This corrects the older findings/systems/guild.md inference that a native
list<MSG> callback proves a bare ret_data array. The actual callback selects a
named child. Returning [] skipped ParseNoties and could retain old native cache
entries instead of replacing them with the replica's empty current collection.

Evidence is bounded original Thumb bytes and RTTI/vtable binding from immutable
DataDump local/inputs/extracted/lib/armeabi-v7a/libnative_core.so, SHA256
c4646ac3817b0008b6ea387fde9c8279fd439343ccc272acdc5883fab9d00eec.
G coordinates use Ghidra base+10000; code ELF/file offsets are G-10000.
Data segment ELF virtual addresses differ from file offsets by1000.

## Exact RequestMsgList callback

RequestMsgList Ga7d48c builds auth5 only; route /guild/GetNotifications resolves
at Ga7d6de. The final uchar is local requester behavior, not a serialized filter
proved here. Exact inner $_32 __function wrapper name string ELF1dfc7aa binds
RTTI VA214f858, vtable VA214f82c, callable ELF a81fdd (Thumb)/Ga91fdc.
Do not use the adjacent plain lambda type spelling, which has no callable
vtable, or infer the wire shape from list<MSG> alone.

Success1 is checked Ga92006. ret_data resolves at Ga92010 and is selected at
Ga92012. Optional my_guild resolves Ga92090, selects Ga92092 and goes to
ParseMyInfo Ga685f0 at Ga9209a. Optional guilds resolves Ga92118, selects
Ga9211a and goes to ParseGuilds Ga6b340 at Ga92126. Most importantly,
**guild_notifications** resolves Ga921d6, selects Ga921d8 and goes to
**ParseNoties Ga6bf08 at Ga921e4**. Callback receives the manager's MSG list
at manager+100 (Ga92238). It additionally forwards ret_data to achievement
ParseLobbyEnter Ga844918 at Ga92228; this is not generic wallet SyncUser.

ParseNoties clears the current manager+100 list at Ga6bf2a..Ga6bf6e before
iterating the supplied child. Thus an empty array under guild_notifications
replaces that collection. An absent child, including the old bare [] response,
branches around the parser and leaves the collection untouched. No fabricated
Guild info or wallet object is needed for an empty notification read.

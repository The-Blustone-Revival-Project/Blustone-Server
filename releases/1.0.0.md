# Blustone Server 1.0.0

The first standalone server release packages the reconstructed local BLUSTONE server, its reference data, launch profile and pinned resource bundle. It brings the existing revival work into a repository that can be installed and run independently. This is the initial release baseline; the Added list describes included functionality rather than claiming it was all developed today.

## Added

- TypeScript/Express compatibility server with a 285-route recovered vocabulary and documented OpenAPI/Swagger surface.
- Local launcher/base-info, selected-server and version responses compatible with the preserved client.
- P-384 shared-secret exchange, HMAC-SHA384 signatures and AES-256-CBC encrypted request/response support.
- Guest/account login, nonempty OTP/session binding, and durable account/transport-key persistence.
- Native-shaped lobby, inventory, owned-card identity namespaces, card-book and deck responses.
- Separate arena attack/defense decks with preserved custom defense selections.
- Hunter reference identities, role/element metadata, levels, training and explicit historical-stat projection policy.
- Original Episode graph, encoded read/clear logs, chapter/story progress and scoped reward settlement/refusal behavior.
- Campaign area/stage identifiers and achievement persistence, with unknown balance fields kept as replica policy.
- Mission admission, start/replay/complete behavior, battle receipts and earned hunter/team EXP.
- Reward handling with owner isolation, durable replay protection, overflow/capacity checks and explicit unsupported cases.
- Search-capsule, hunter-trace, recruitment, tutorial, helper and repeat-search compatibility contracts.
- Login bonus, mail and Special Supply receipt/persistence behavior.
- Shop fuel, rank-up and skill-training contracts with focused persistence/rollback tests.
- Arena preparation/settlement contracts and local compatibility references.
- Conservative fishing, mirage and gem contracts that refuse unreconstructed mutations.
- CDN resource manifests, range downloads and PKGI tree/container serving.
- Pinned E6 runtime profile with 139 packages at resource/reslist/header stamp `1634683`; E7 remains inactive.
- Repo-local recovered Episode JSON, campaign/environment evidence, catalogue strings and historical archive inputs.
- Original local 100×100 profile portrait used by the native client.
- Resource preflight and SHA-256 verification for 968 imported files.
- Portable runtime/test-reference resource bundle with a manifest-checked safe importer/exporter.
- Windows foreground launcher, development launcher and explicit network/state overrides.
- Persistent working state under ignored `var/`, with private retained migration backups under `local/`.
- Optional Dockerfile/Compose configuration; container runtime has not been validated in this release.
- Complete 48-script server test chain and an external-process compiled-server verification tool.
- Release policy, semantic versioning, changelog and reproducible publication tooling.

## Improved

- Server installation no longer depends on the retired workspace path, a sibling DataDump checkout or a preserved phone directory.
- One explicit current E6 launch profile replaces conflicting historical smoke/device defaults for normal startup.
- Required resources are checked before startup; missing packages produce an actionable failure.
- Reference inputs and package fingerprints are pinned to preserve source provenance and detect accidental changes.
- Private state, raw archives, logs, toolchains and proprietary runtime binaries are excluded from ordinary Git contents.
- Documentation distinguishes reconstructed native contracts, local fixtures, unsupported systems and host verification from native gameplay evidence.

## Fixed

- Removed parent-directory searches for the Episode catalog and native route vocabulary.
- Replaced default runtime-package paths pointing at a recovered phone's private files.
- Corrected asset resolution so the profile portrait also works from compiled JavaScript.
- Repointed resource/evidence tests to repo-local inputs rather than the old workspace.

Validation: dependency install, all 48 test scripts and TypeScript build passed. A compiled process launched from an unrelated working directory passed encrypted ECDH/HMAC/AES traffic, authenticated lobby/reference/Episode routes, all 139 resource rows, HTTP206 ranges, portrait delivery and credential/transport persistence across restart. All three preserved gameplay states remained exactly equal. No new native battle or Android UI test is claimed.

Install: clone this tag, run `npm ci`, import `Blustone-Server-Resources-1.0.0.zip` with `python scripts/resources/bundle.py import <file>`, run `npm run resources:verify`, then `npm run build` and `npm start`. The bundle contains game resource/reference files, not account saves, transport keys or signing material. Preserve existing private state separately when upgrading.
